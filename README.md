# The best PPT builder

本地单用户的 PPT Agent 网站。输入一句话后先完成背景调研和需求确认，再自动生成结构板、页级资料、策划稿、设计稿，并导出 PPTX。

## 本地运行

需要 Node.js 22.18.0 或更高版本。

```bash
npm install
npm run dev
```

打开 http://localhost:3000

1. 先到「设置」填写文本模型、SVG 模型和搜索模型
2. 回首页输入主题，开始生成
3. 背景调研完成后，在「内容需求单」中确认系统推荐的关键答案
4. 空间结构板会把章节、页面、资料、内容策划、初稿和设计稿放在同一张可平移缩放的画布中；右侧 Script Desk 可按整套、章节或当前页生成修改提案，用户预览 diff 后再应用
5. 所有资料完成后，系统用一次文本模型调用生成整套 Deck Plan，再按共享字阶、网格、标题区和视觉槽位生成统一初稿
6. 全部初稿完成后进入第二个默认停顿点：由 AI 规划并生成封面与正文背景、预览和调整，或上传 PPT、PPTX、PDF 提取视觉规律；确认后才生成最终设计稿
7. 编辑工作台通过「搜索 / 初稿 / 设计稿」查看同一页产物，右侧阶段卡展示整份进度并支持当前页改稿
8. 全部设计稿完成且每页通过 SVG 可渲染检查后，从导出菜单选择「可编辑 PPTX（推荐）」或「高保真 PPTX」

API Key 只存在本机 SQLite（`data/ppt-agent.db`），不会进仓库。

## AI 原创背景

设计确认面板提供「AI 原创背景」。每份演示先根据主题、受众、目的和逐页内容，由文本模型规划独有的视觉概念，写出材质、主辅光、空间层次、构图、配色与文字安全区，再通过 GotoCC 分别生成封面和正文背景。界面不再把固定主题模板作为默认选择。

可以直接「AI 生成两张背景」，也可以先看完整提示词、编辑后再生成。正文继承封面的视觉母题、材料和色彩，同时为信息区域降低细节对比。背景图不含文字、Logo 或数据；最终文字和图表仍由设计模型独立排版。艺术指导提示词和输出规范见[背景生成说明](./docs/background-generation.md)。

设置页只需填写独立的 **GotoCC 图片 Key 和模型**，使用页面统一的「保存配置」按钮验证并保存。默认模型为 `gpt-image-2`；尺寸由 AI 按封面与正文的构图分别选择，缺省为 `auto`。无需填写分组或重复勾选确认，旧配置继续兼容。

每次图片生成会消耗 GotoCC 余额。超时、取消、5xx 或结果读取失败不会自动重试；已成功保存的图片保留，手动重试只补未完成的部分。程序重启后也不会自动重复不确定的图片请求。生成完成只提供待确认方案，不直接覆盖已有设计稿。

确认新视觉方案后只重做设计稿；同一视觉方案可用「仅替换整套背景」调整图片或强度，保留已有文字与排版、不调用模型。完成后的入口是「主题与背景」。样张使用当前内容，已有设计可查看精确的背景替换预览。

背景真实内嵌进 SVG 和两种 PPTX；可编辑导出中为独立图片。支持手动替换 PNG/JPEG/WebP，单张最多 10MB、2400 万像素，每项目最多 20 张，按 16:9 居中裁切为 1280×720 JPEG。上传文件、提示词、生成状态与背景都保存在 `data/artifacts/<projectId>/themes/`；图片配置保存在权限为 `0600` 的 `data/image-settings.json`，均不提交。生成时，内容摘要发送给文本模型，背景提示词发送给 GotoCC，实际背景再作为 SVG 模型的视觉输入。

## PPTX 导出

「可编辑 PPTX」把 SVG 的文字、基础形状、线条、路径和嵌入图片转成 PowerPoint 原生对象。标题、正文和数字可以修改，普通图片可以替换和裁切。渐变、蒙版等复杂效果在对应元素或分组转成图片，下载后会提示数量和所在页；复杂全局样式可能扩大图片化范围。旧 SVG 不要求补写语义属性。

「高保真 PPTX」把每页渲染为 2560×1440 PNG，完整保留页面画面并沿用文字锐化规则，适合直接放映。页面内的文字和形状在该模式下不能独立修改。

两种模式都由 PptxGenJS 生成标准 PPTX 包，保留 16:9、页面顺序与演讲备注，导出不需要 Office、Python 或浏览器服务，也不调用模型。文本字体不会嵌入文件，生成端和打开端都需要合适的中文字体；默认按系统选择冬青黑体、微软雅黑或 Noto Sans CJK SC。跨系统字体替换可能改变字宽，交付前应在目标 WPS / PowerPoint 中检查。

完整的[支持与降级范围](./docs/architecture.md#pptx-导出)、[样例生成和人工验收](./docs/operator-runbook.md#pptx-样例与打开验收)、[上游技术决策](./docs/editable-pptx-decision.md)可供维护时参考。

运行环境需要 **Node.js 22.18.0 或更高版本**。导出在有超时和预算的子进程内运行；[持续回归与依赖安全说明](./docs/export-ci.md)列出维护命令与尚未由上游发布修复的已缓解公告。

## 设置说明

- 文本模型、SVG 模型、搜索模型各用一套独立配置；背景图片使用单独的 GotoCC 配置
- 协议：OpenAI Responses / Messages / Gemini `/v1beta/models` / `/v1/chat/completions`
- 搜索模型：与另外两套模型一样填写 Base URL、API Key、协议和模型名，并支持拉取模型列表；所选模型需要自身具备联网搜索能力
- Grok：搜索模型协议必须选择 OpenAI Responses，应用会启用 `web_search`、结构化来源和 SSE 流式接收；Chat Completions 只会生成普通文本，不能作为 Grok 联网搜索协议

通过兼容网关调用 Grok 时，搜索过程会在需求调研页和工作台右栏显示“请求已提交、正在搜索网页、正在整理来源”等实时状态。遇到限流、模型容量已满、临时不可用或网关超时，应用会自动退避重试，并显示等待秒数和重试次数；暂停项目会中止等待。HTTP 524 的 HTML 错误页会被收敛成简短提示。若多轮重试后仍持续出现 524，需要更换能透传 Responses SSE 的网关或直接使用 xAI 接口。

OpenAI Responses 请求会保留 system/user 角色，并传递页面生成所需的输出 token 上限。

## 架构与调用预算

- 模型、搜索等长任务不占用 HTTP 请求生命周期；动作接口登记任务后返回 `202`，同一项目由单 worker 串行处理
- 暂停、重跑和改稿会用项目级 `AbortSignal` 中止旧请求；改稿指令成功落库后才出队
- 页面先批量完成检索，再用一次文本模型生成 Deck Plan，随后批量生成初稿；用户确认设计参考后才批量生成设计稿，减少供应商并发容量错误
- 初始调研和每个内容页都只做一次复合搜索；封面、目录、章节和结尾复用项目级资料
- 大纲与最终内容页 SVG 保留原帖公开 Prompt 核心；内容页最终设计严格使用 Bento，封面、目录、章节和结尾使用独立页型提示词
- 参考稿只在本机保存和分析，最多 50MB、40 页，最多抽样 12 页；不把参考稿中的事实、Logo、品牌或图片带入新演示
- SVG 只有通过独立根节点提取、XML 解析和实际渲染检查后才算完成；历史坏稿可无损提取时自动修复，否则降为待重生成并阻止放映或导出
- 12 页、约 7 个内容页且使用内置风格的正常主链路目标约 35 次模型请求；上传参考稿只额外增加一次视觉分析调用
- 项目页只读取一次初始快照，之后通过 SSE 接收变化，不同时运行轮询

## 内容资料与图片上传

首页「内容资料」支持多选和拖放图片、TXT、Markdown、JSON、PDF、DOCX、ZIP。单文件最多 50MB，一批最多 20 个文件、合计 100MB；ZIP 解压最多 2000 项、256MB。暂不支持加密、分卷、ZIP64 或非 UTF-8 文件名的 ZIP。内容上传与「设计参考」分开：前者用于事实、文案和实际配图，后者继续只用于提取风格。

图片经签名与尺寸检查后会以实际视觉输入交给已配置的 SVG 模型，再以内嵌图片进入策划稿、设计稿和可编辑 PPTX。不调用额外图片服务。图片、原件和来源记录保存在本机 `data/artifacts/<projectId>/content-materials/`；为完成生成，选定正文和页面相关图片会发送到用户配置的模型接口。

「按资料包中的逐页方案制作（如有）」会读取材料包里的 `slides.json`，导入标题、正文、顺序、讲稿、引用、图片关联和备用页属性，再走原有 Deck Plan、策划稿、设计确认及导出流程。没有逐页方案的材料按普通资料使用；未上传材料的项目维持原有流程。导入上限 80 页；备用页在 PPTX 中隐藏。材料中的命令、角色指令和旧坐标不会执行，整页预览不会作为最终幻灯片。

PDF 使用本机 `pdftotext` 提取文字，可通过 `PPT_AGENT_PDFTOTEXT` 指定路径；没有文字层或缺少工具时保留原件并显示提示，可补传截图或文字。DOCX 提取正文；HTML、可执行文件等不支持类型会在资料摘要中列明，不执行。若单独上传图片而未提供图注，模型只能描述画面可见内容，不能推断人物身份或日期。

创建接口仍兼容 JSON，也接受 multipart：`requestText`、可选 `brandTemplateId`、重复的 `files` 和 `usePreparedPlan=true/false`。解析成功并保存全部资料后才启动项目 worker；不会更改数据库结构或现有模型配置。

## 不会上传的内容

- `data/` 里的数据库（含 Key 和你的项目）
- `.env` / `.env.local`
- `node_modules`、`.next`
- `output/` 里的演示文稿、预览、备份和本地验证产物
- `assets/site/` 里的用户截图，以及指定用户项目的临时改稿脚本
